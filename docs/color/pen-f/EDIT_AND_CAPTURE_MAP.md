# PEN-F COLOR edit, capture and completion map

Build **3101**; addresses are hexadecimal. Property/task IDs are decimal unless prefixed `0x`. This appendix maps stock call paths and the HSL extension's integration contracts without treating separate probes as one full-camera replay. Field layouts are in [STRUCTURES.md](STRUCTURES.md).

## 1. Editor dispatch and a single saturation commit

```text
GUI_TASK entry 0x60c72e76 → 0x60bb914e
  GUI receive 0x60bb9321
  → global prefilter 0x60d12112
  → selected FSM from 0x6160c04c
  → 0x60bcba52 / editor dispatch 0x60bcba4d
  → local handler 0x60cefd3d
  → controller 0x60cd03cc
  → parent actuator 0x60c73065
  → COLOR Up 0x60cb0684 / Down 0x60cb08e5
  → selected child: 0x9004/0x9006 step, then 0x900c commit
  → COLOR child override 0x60c836cd
  → generic child commit 0x60c80913
  → GUI property setter 0x607363b3
  → explicit-value adapter 0x6075fbed
  → 0x602b9dac → 0x602badc5
```

The child step changes its temporary enumeration index before commit. Internal event `0x900c` is generated by the Up/Down action; it does not mean a physical OK press. Native dial callback `0x60cb1422` handles event `0x9032`, reading a signed count through `0x60d157f8` from `0x6161bf92`. Count−1 requests Up, +1 Down, zero no commit. Setter `0x60d157ef` is the upstream count producer; physical rotation direction is not inferred from the sign. Callback `0x60cb166f` handles sector movement.

The GUI task is dynamically requested by `0x60bb8d4b`, with descriptor words `[0x60c72e76,1,0x2200,0]`; its observed stack-size field is8704 bytes. The selected FSM is constructed at `0x61a8a0c0`. A synthetic test task-ID witness must not be published as the camera's dynamic GUI ID.

### Held OK is a separate gesture

| Event/stage | Native behavior |
| --- | --- |
| OK press `0x900c` | COLOR callback `0x60cb1ad1`; base dispatcher `0x60c7329d..0x60c732f3` starts timer 537 with duration argument 1000 |
| Parent state | +16=3, pending event+20=`0x903e`, hold marker+44=1 |
| Timer translation | `0x60beed67`, key `537−499=38`, row `0x60de18ac`, callback `0x60bef6fb` produces GUI event `0xf802` |
| Hold expiration | `0x60c73419` dispatches pending `0x903e` to COLOR callback `0x60cb190e` |
| Reset iteration | `0x60cb194c..0x60cb1999` visits cursor plus 12 children; requests each default, then commits valid values through ordinary `0x900c` |
| Release `0x900d` | Cancels timer/pending event; after completed hold, does not exit the editor |
| Short press/release | `0x60cb1937 → 0x60c7366a` requests normal exit, reaching `0x60d137b7` |

The existing default getter plus ordinary setter therefore controls what an H/S/L-axis reset means. It is not necessary to invent a second bulk-write algorithm. Timer argument units and physical input timing are outside these GUI-event contracts. ALL uses cursor 255, not a thirteenth HSL sector.

## 2. Public-setting guards and active-profile refresh

The GUI setter reads shared capture status through `0x606b6ba1`, with resource 5 locked only around each individual read. Writer `0x606b761a` ORs a mask into one of four words; the high nibble chooses the word. Clearer `0x606b68f9` clears selected bits or the group.

| Tested capture status | GUI COLOR write result |
| --- | --- |
| All zero | Passes this guard |
| Word 0 bit `0x2` | Rejected |
| Word 0 bits `0x2|0x4` | Passes this guard |
| Word 1 bit `0x2` | Rejected |
| Word 1 bit `0x2` plus word 0 bit `0x100` | Passes this guard |
| Word 2 bit `0x2` | Does not trigger those rejection branches |

Other eligibility checks still run. These exceptions preclude describing the object as one universal “busy” flag.

After guards, call `0x6073654f → 0x606b6236(1)` sets the native edit-in-progress word `0x61600980`. The setter clears it via the same function at `0x607365b1`, after manager completion. Shooting predicates use `0x6082bf54 → 0x606b5c49`; the tested block `0x6082d12b..0x6082d154` rejects when it is set. It remains set across the request wait, acknowledgement, timeout/retry and completion delivery until the original GUI stack resumes.

This preserves a real stock coordination mechanism, but is not a single lock covering check-plus-write. A forced status change at `0x60736547`, between the guard and flag set, still permits the write. That demonstrates the local instruction contract, not a reproducible camera race.

The registered current callbacks are:

| Stored profile | Current callback | Staged callback | Public mode |
| --- | --- | --- | ---: |
|COLOR1|`0x602c1067`|`0x602c59bd`|54|
|COLOR2|`0x602c1080`|`0x602c59dd`|55|
|COLOR3|`0x602c1099`|`0x602c59fd`|56|

Each current callback checks effective 111 and refreshes only when its profile is active. Editing an inactive profile changes storage without refreshing the selected image settings.

```text
0x602c50be(context=0 current / 1 staged, public mode)
  → 0x602c414a: build152-byte parameter structure
      COLOR1 case0x602c497d
      COLOR2 case0x602c4a9e
      COLOR3 case0x602c4bbf
      twelve signed32-bit values at +80…+124
  → 38 derived writes through0x602bc3e3
  → effective saturation IDs919…930, record0xf6ea
```

One derived write (property 397) reaches recording-mode notification `0x6030981f → 0x60537a56 → 0x60537d56`. It occurs **before** the twelve effective saturation writes; the refresh is not established as one indivisible memory update.

The notification calls reservation-mode update `0x60549311 → 0x60549048 → 0x6054a837`. Pool descriptor `0xa1c69320` has 24 slots; mode 1 reserves 8, yielding mask `0x00ff0000` at+64. Constructor `0x60547d3e → 0x6054a6e4` and manager initializer `0x60548891` must both have run. The latter clears packed software locks at `0xa1c6c38c` via `0x60549d3e`. This is buffer-capacity reservation, not an ISP upload.

The bounded refresh executes native lock-bit and reservation arithmetic with reviewed uncontended exclusion interfaces: interrupt save/restore `0x60086c0b/0x60086c54`, hardware semaphore `0x60070bc0/0x60070cb1` for `0x1e18001e`, and rec_mem semaphore 99 through `0x60069606/0x600696f9`.

## 3. Application request, reply and natural redraw

For application state `0x10000 < state <= 0x1ffff`, helper `0x607607a1` constructs request `0x404e`. Outside that gate it skips this exchange; state zero is a useful control, not an asserted normal editor state.

```text
0x607607a1
  → stack receiver0x606f1117
  → responder lookup0x606f11d6 →0x606f1362 →0x606f13b6
  → shared responder constructor0x6075da43 / reply wrapper0x606f2724
  → event constructor0x606c003e
  → send0x606f11e8 → request/wait0x606f19c2
  → select target0x6075d593 →0x60934b16 →0x6093464e
  → queue adapter0x6095147e
  → private semaphore wait0x606b5072
```

The editor's worker waits while **task 64**, entry `0x606b4869`, executes `0x60952058(0) → 0x60951be7` inline. The framework adapter's stored creating-task ID need not be64; USTART4 can construct it before task 64 starts.

Native pump and active NEW-component route:

```text
0x60951be7 pop →0x60951b2b dispatch
  → event-target virtual+24 →0x609326fc
  → NEW dispatcher0x60927c2e →0x6092a04a →0x609287a9
  → request branch0x60929d14
  → reply registration0x60931c41
  → action0x608042d1
      sequence/cache predicate0x607e11a2 →0x608189b7
      temporary type-bearing0x404e
      completion0x60931e5f →0x6093212d
  → acknowledgement11771 (0x2dfb)
  → completion11770 (0x2dfa)
      0x606f1c9c →0x606f1cc3 clears result and releases private semaphore
```

The original request, acknowledgement and completion are separate queued objects. Acknowledgement does not release the caller. The temporary `0x404e` is for response lookup and is not another queued edit. A warm sequence cache returns 0 without sequence restart; a stale picture-mode cache reaches `0x608038b2` (`changeSequence`) with argument 2 instead. The larger sequence-change path is outside the normal warm-cache completion contract.

Caller timeout−1 becomes repeated 1000-unit waits, with diagnostics after 5000; there is no demonstrated finite fallback for an unanswered sent request. By contrast, failure of the 32-byte event allocation yields an error that this helper does not propagate, so the edit proceeds. Those are different failure modes.

After actual completion, the original setter continues:

```text
0x60760063 →0x607600e2: immediate listeners
  → append property to manager+560
  →0x606bb556: schedule delay20, callback0x6075fecb
  → return through child/parent/controller
  → controller call0x60cd04b7 → viewer0x60c84901
  → all four viewer callbacks → display records179/209
```

The four reviewed general listeners are `0x606ba61c`, `0x606da12e`, `0x606ef6eb`, `0x6075c8e0`. For COLOR edits the second writes 1 at ShootArchitecture+252 through `0x606dd6c3`; the other three return after unrelated-key tests. A later timer callback `0x606bb5de` submits work through `0x6008593a`; worker `0x6075fecb → 0x607601b5` drains pending IDs into notification groups. COLOR reaches generic group 0. Direct viewer return does not require inventing immediate execution of this delayed worker.

### Active-state provenance

The native NEW constructor is `0x60927b64`, derived-state reset `0x60927bf8`. Initialization-success producer `0x60928595` sets substate 10 and queues decimal event 11562. Dispatch follows `0x609280b4 → 0x6092809b → 0x6092804d → 0x60806a75 → 0x6080aa2a → 0x60928744`, selecting self, entering parent state 4 and then running state 14 through `0x6092a01b`.

Active publication `0x60803b3c` writes global `0x61606058` **before** media readiness. It queries selector 23, API `0x602f1c93`, and mask `0x3080`. A supplied clear physical-status result reaches 14; supplied error bits reach callback `0x60803ced` while state 14 is not yet entered. Published pointer alone is therefore insufficient readiness evidence.

Root/mode/category event 3345 handlers `0x609360d3`, `0x6094af5f`, `0x6094bb12` install pending children; the category queues its own success event. Native selection and completion execute in bounded fixtures, while external constructors, event 3345's preceding switch handshake and the physical media result remain explicit boundaries.

## 4. Bank changes and publication timing

Paired save is `0x6075fb08 → 0x607600be → 0x602ba24d/0x602ba141 → 0x602bdaa5 → 0x602bdb3e → 0x602f067a`. It saves all three profiles into the corresponding custom/dial pair. A later live edit does not automatically resave that pair.

Registered dial recall is `0x602ba07b → 0x602bd80f → 0x602bd5f0`:

| Boundary | State/operation |
| --- | --- |
| `0x602bd696` | Destination ACTIVE already loaded; committed current settings may still be source |
| `0x602f0a2c → 0x602f0b12` | Stage ordinary and additional parameter groups |
| `0x602bd508`, `0x602bbf60(1)` | Consistency and pre-commit callbacks; context 1 COLOR refresh |
| `0x602f0b80` | Compare staged values, write current records, collect changed IDs |
| `0x602f0c58` | Update live representation as part of commit |
| `0x602bd7f9` | Public inhibit byte cleared; post-commit callbacks still pending |
| `0x602bbf60(0)`, `0x602bc01e` | Post-commit callbacks and changed-ID notifications |

The common commit return tail at `0x602f0c52` is a useful publication boundary for the H/L extension. Reading ACTIVE earlier at capture time could combine destination H/L with source S/mode. Context 1 refresh must not publish those staged H/L as live.

Temporary MyMode `0x602ba1bd` differs from dial recall: its static tail restores old bank 41 and sets 569. ShortcutMyset `0x602ba0fb` uses staging route `0x602bcd16`. Bank 41 alone cannot therefore identify every current H/L owner.

Public inhibit getter/setter `0x602f0d0f/0x602f0d06` manipulate byte `0x6189a4b0`. Public setter `0x602b9f33` rejects while it is1; internal writer `0x602f02b4` and capture getters still operate. It provides no standalone atomic-snapshot guarantee.

## 5. Capture allocation and immutable value copies

```text
0x602496d8 initialize slot table
0x60249718 take semaphore25 →0x60249743 choose slot/resources
  →0x605488ae(type0x1500) allocate handle
  →0x60548b10 resolve pointer
0x6025350c populate capture
  →0x60249c22 validate slot1…40 and ownership bit4
  →0x6054c52b copy22080-byte base
  →0x60253b36..0x60253c7f capture mode/profile/S values
```

Full native population, held A/B captures, registered edits, profile switch and release/reuse establish value-copy lifetime. Release `0x6024992a → 0x60249ecf` clears ownership and releases the handle; old pointer bytes remain. A new owner at the same address must overwrite its whole associated H/L row.

The lower capture worker is task 127, entry `0x60234846`, priority 25, stack `0x700`. Its20-byte state rows start at `0x60331fa8`. State 12 (`StlRdy1`) registers callback `0x6024a94b`, mask `0x04008000`, through `0x60235450`. Callback scanner `0x60235528` tests two lower status words `0x61865834/0x61865838`, not the GUI capture-status array. When the first mask clears, dispatcher `0x60234c0d` enters state 13 (`StlRdy2`) at `0x6024a95b`, whose conditional population call is `0x6024ab30`.

Task 127's input contracts are distinct:

| Input | Shape | State-row table | Example |
| --- | --- | --- | --- |
|mailbox 1/event 78 bit 1|12 bytes, command+4|row+16|command 18 clears `0x04000000` via `0x6024a919`|
|queue 100/event 78 bit 2|16 bytes, operation+8|row+12|Capture requests|
|queue 109/event 78 bit 4|12 bytes, command+4|row+16|reply 43 clears `0x8000` via `0x6024a932`|

Command 18 comes from operation 47 on task 125/queue 104, callback `0x6024b3b8`, through `0x601ca2a3 → 0x601ca1ec`. Reply 43 comes from external-flash task 120/queue 96 (`STB_EXTERNAL`), not a settings lock. In its tested operation 2 tail, a zero reply status can be sent even when peripheral work is skipped; it must not be described as measured flash readiness.

### Two large-capture converters

Both preview/recview and still callers supply a376-byte descriptor with the capture pointer at+124 to converter `0x6052010f`. Call sites are `0x6051c78d` and `0x6051d4e9`; preceding accessor `0x60521f80` resolves the owned capture. COLOR narrows halfwords to bytes at `0x6052056e..0x605205f9`, placing them at processing-parameters+5684.

Saved recording also uses separate converter `0x60531fdb` (`rec_ImgPro_ImageParam`). Its analogous H/L insertion boundary is `0x605323f8`. Covering only `0x605205f9` is insufficient: preview can change while the saved JPEG remains neutral. The independent recording copy is supported by both native conversion and physical capture comparisons.

## 6. Compact acquisition and worker handoff

```text
0x60554c7c: choose one of five free632-byte slots
  →0x60557bcf: build from309-byte request, state1, queue index
  →0x60558eb8 enqueue /0x605569d3 dequeue
CPU2 task0x2002, entry0x60574c5a
  → event handler0x6057599a, state1→2
  →0x60557319 full per-frame refresh
  →0x6055761d copies effective S into slot+382
```

Acquisition occurs on state 1→2, **not** at enqueue. A profile edit after enqueue but before acquisition is included; a later edit leaves the acquired values unchanged. State 2 re-delivery consumes the queued item without another refresh. `slot+204 & 0x8000` can skip the refresh.

State setter `0x6055619b → 0x60556293 → 0x60557305` uses reviewed hardware lock `0x121a0012`; its exclusion ends before the current-index store and full settings refresh. It is not a lock spanning all twelve S reads.

The active per-frame conversion is:

| Stage | Native code | Saturation representation |
| --- | --- | --- |
|Acquired slot|`0x6055761d`|+382, 12 signed halfwords|
|212-byte descriptor|`0x6055e7a7..0x6055e7b3`|+37, 12 signed bytes|
|1852-byte temporary|`0x6055e059..0x6055e0ae`|+1703, 12 signed bytes|
|6032-byte job parameters|`0x6056d418`, copy `0x6056f96a..0x6056f97e`|+5684, 12 signed bytes|

Shared-job construction is reached through `0x6056d081 → 0x604c1c0a`; handle publication is `0x6055a0d2`. Conditional configuration copy `0x6055a0e2 → 0x605553bf` updates the reusable global snapshot. **Per-frame** update `0x6055a209` is separate from construction/configuration comparison and is the useful H/L transport contract.

The sender allocates/copies a208-byte descriptor through `0x6057799c`, then sends queue `0x200c` via `0x6056a248 → 0x60069429`. Receiver task `0x2006`, descriptor `0x6003d938`, entry `0x605725af`, startup argument 1, priority 25, stack 5632, selects operation 1 handler `0x60573883` through `0x605729f4/0x60572a48`. It obtains the acquired slot through `0x605553f2(kind2)` rather than rereading current UI settings.

Two bounded receiver outcomes remain important:

- Zero upstream flags select blank-frame branch `0x60572b67`, which still performs image-fill work rather than immediate completion.
- Supplied upstream request byte 107=1 propagates to compact+172 and selects ordinary branch `0x60572e70 → 0x6055a312 → 0x6056d637 → 0x604c2447`. The physical producer meaning of that bit is unqualified. An uninitialized quality record+29 can propagate via compact+597/configuration+19 to job+23=0, making geometry getter `0x604bcfd7` return null and consumer `0x604c38dd` fault. This is a missing fixture configuration, not evidence of a camera failure.

Static receiver completion uses `0x60571903`; descriptor+70 in3…6 reaches free `0x60573d7c`, while the tested class 1 replies through `0x60572646` with the descriptor pointer. Full ordinary compact completion/reply-to-origin/free/reuse is not claimed by those receiver probes.

Compact resource release has stronger separate evidence: retain `0x60548a92`, release `0x6056bfcf → 0x605489a5`, and final-count-zero notification `0x60556899` clear the matching slot handle/state. Full exposure callback `0x60245d55 → 0x60550562 → 0x60554e3d` executes in bounded inputs. Its real arrival and relationship to the ordinary CPU2 worker tail are distinct questions.

## 7. Job submission, completion and H/L consumer

```text
0x604c1c0a construct job + companion
  → capture/compact conversion
  →0x604c20ce prepare
  →0x604c2447 stage dispatch
      0x604c3051 packs1132-byte request
      0x604f747f selects HSL builder
      COLOR call site0x604f7506, rejoin0x604f750b
      0x604b3eb0 →0x604b3fd2 →0x604b473e ISP submission/start
  →0x604c2732 finish, waits flag219/0x80000000
  → supplied completion status; native IRQ98 handler0x604bd30c
      callback0x604c4011(record,event9)
  →0x604c2c28 cleanup
  →0x604c2082 destroy
```

Worker `0x60518d86` calls submission then finish. The qualified job path uses submission mask `0x80003019`, hardware slot 0 and IRQ98. The tested completion requires engine status 256 and secondary status 1 with the installed masks; missing/masked statuses do not signal completion. Clock/LUT/coefficient registers are captured writes, not simulated pixels.

The callback records status and signals completion through `0x604bec50`; it does **not** free the job. Finish releases the stage token/processing ID/hardware reference, clears the operation record and marks the hardware slot inactive. Destruction then releases job/companion allocations. Inactive hardware records may retain stale callback bytes, so the active flag matters.

Native record selector `0x604c2ef9`, submission wrapper `0x604c2f1d` and validator `0x604c3f93` accept all sixteen 52-byte job records. The H/L consumer must recognize the selected valid record, not require record 0. Once H/L is copied to job+14920, subsequent UI edits and source-slot reuse cannot change that job's coefficients.

A completed job's submission can return success without running another image. Reuse requires preparation `0x604c20ce`; tests retain that no-work control rather than resetting hidden flags from the host. Under both tested ISP banks, H/L coefficient changes upload even with a warm LUT cache. That does not settle every earlier compact configuration-cache decision.

### Lower HSL/tone configuration boundary

The outer static relationship is `0x604a6821 → 0x604b38c5 → 0x604aa595`; dispatcher `0x604aa595` indexes table `0x605f6b20` using request byte+`0x10`. Kind 0 selects `0x604aa68a → 0x604f2973`. This kind selector is separate from picture-mode key+`0x0a`. Bounded native configuration tests begin at `0x604f2973`; they do not execute every outer scheduler call.

Kinds 0/14 with request-type high byte 1/2 select wrappers `0x604f88e3` or `0x604f8911`, both entering common builder `0x604f8543`. The normal branch calls HSL selector `0x604f747f → 0x604f7272`, then tone builder `0x604f7c76`. Predicate `0x604f2a64` selects a narrower bypass for request byte+1071 in1/2/3 and halfword+12 equal to `0xa200`/`0xa600`:`0x604f746a` disables HSL while retaining a default tone pointer. This is not a bypass of the whole JPEG pipeline.

Dispatcher `0x604b4933` sends coefficient and LUT operations to two hardware-bank pairs:

| Selection mask | Coefficient bank | LUT bank |
| --- | --- | --- |
|`0x8`|`0x9e001800`|`0x9e00a400`|
|`0x10000`|`0x9e005800`|`0x9e00cc00`|

Writer `0x604b5006` copies 73 words from color output+`0x2a4` to coefficient bank+`0x2d8`; these include all twelve sectors and the control word. LUT writer `0x604b58c4` follows. It uploads 128 entries for each of ten HSL pointers (halfwords zero-extended where applicable), plus 256 tone entries from output+`0x1230`. Cached tags at `0xa1c61df8` and context dirty bit `0x4` can suppress/re-enable LUT uploads. The coefficient copy precedes that cache decision, so a warm LUT cache does not suppress changed H/L coefficients in the qualified paths.

The source LUT arrays have 96-entry subdivisions, while these hardware uploads read 128 entries. The surplus can include neighboring source data. Native continuation did not overwrite it; physical Yellow-lightness experiments did not expose an image failure. That does not identify which surplus entries the silicon ignores. Preserve the actual transfer lengths when reproducing the register contract.

## 8. What is and is not serialized

The bounded tests establish independent A/B capture values, acquired compact values, copied job values and native completion/destruction under declared OS/peripheral contracts. Physical tests establish the integrated edit's live-view/JPEG behavior in exercised modes. Neither proves arbitrary RTOS scheduling or every sensor/ISP state.

Two forced overlaps show why the lifetime distinctions matter:

1. Pause large capture at `0x60253c07` after six sector reads, switch profile, resume: the capture contains six old and six new S values.
2. Pause publication at `0x602c5248` after six effective writes, run CPU2 compact refresh, resume: the compact slot contains a mixed array.

These demonstrate that the scalar loops themselves are not atomic. They do not demonstrate that ordinary camera event generation permits the forced schedules. The extension preserves stock admission/publication/acquisition boundaries and transports H/L with the image; it does not claim a new global transaction lock or rely on task priority to serialize different CPUs.
